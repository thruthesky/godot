# 다국어 (i18n) — 공식 방식 그대로, 실측으로 확인한 것

> **이 문서로 오는 상황** — 화면 문구를 여러 언어로 바꿔야 할 때. 장치 언어를 따라가게 할 때, 사용자가 언어를
> 고르게 할 때, 언어를 바꿔도 화면이 안 바뀔 때, 한글·한자·힌디·아랍·벵골 글자가 **네모(□)** 로 뜰 때,
> 우르두에서 UI 가 좌우로 뒤집힐 때.
>
> **정본은 Godot 공식 문서다** — [Internationalizing games](https://docs.godotengine.org/en/stable/tutorials/i18n/internationalizing_games.html) ·
> [Localization using spreadsheets](https://docs.godotengine.org/en/stable/tutorials/i18n/localization_using_spreadsheets.html) ·
> [Localization using gettext](https://docs.godotengine.org/en/stable/tutorials/i18n/localization_using_gettext.html) ·
> [Locales](https://docs.godotengine.org/en/stable/tutorials/i18n/locales.html).
> **이 문서는 그 위에 "실제로 돌려 보니 이랬다"를 더한다.** 공식과 다르게 말하는 곳은 없다 — 다르면 공식이 맞다.

**라리엔 3D 의 결정은 여기가 아니라 게임 SSOT 에 있다** — 지원 언어 7종·화면의 모든 텍스트를 번역한다는 규칙은
[game/references/SSOT.md §8](../../game/references/SSOT.md) 이고, 근거는 [game/references/design.md 결정 9](../../game/references/design.md) 다.
이 문서는 **엔진을 어떻게 쓰는가**만 담는다.

## 1. 번역 표 — CSV 가 기본이다

공식은 **CSV 와 gettext `.po` 두 가지**를 지원한다. 둘 다 엔진이 임포트해 `Translation` 리소스로 만든다.

### CSV 형식 (공식 "Localization using spreadsheets")

```csv
keys,en,ko,ja
GAME_TITLE,Laryen,라리엔,ラリエン
GUEST_LOGIN,Guest Login,손님 로그인,ゲストログイン
WELCOME_USER,"Welcome, {name}","환영합니다, {name}님","ようこそ、{name}さん"
```

| 규칙 | 값 |
|---|---|
| 첫 열 | `keys` — 번역 키. 관례는 대문자지만 **아무 문자열이나 된다**(라리엔은 2.5D 의 camelCase 키를 그대로 쓴다) |
| 언어 열 | **유효한 locale 코드**. `en`·`ko`·`zh_Hans` 등 |
| **`_` 로 시작하는 열** | **주석 — 임포터가 무시한다.** 번역가용 설명을 `_description` 열에 넣어도 안전하다 |
| 인코딩 | **UTF-8, BOM 없이.** Excel 은 기본이 ANSI 라 깨진다 → LibreOffice·Google Sheets·스크립트로 만든다 |
| 쉼표·줄바꿈·따옴표 | 큰따옴표로 감싼다. 따옴표 자체는 `""` (`QUOTE,"""Hello"" said the man."`) |
| 복수형 | `?plural` 열 — 🛑 **쓰면 Control 자동 번역이 안 된다**(공식 명시). `tr_n()` 을 손으로 불러야 한다 |
| 문맥 | `?context` 열 — 같은 원문을 화면마다 다르게 번역할 때. 역시 `tr()` 을 손으로 |

### CSV 냐 gettext 냐

| | CSV | gettext `.po` |
|---|---|---|
| 파일 수 | **1개**(언어가 열) | 언어마다 1개 |
| 7언어 완전성 검사 | **한 행에 빈 셀이 있는가** — 한 번 순회 | 파일 간 키 교차 비교 |
| 복수형 엔진 | 없음(`?plural` 은 자동 번역 포기) | **있다** |
| 번역 플랫폼(Weblate 등) | 약함 | **강함** |
| 스프레드시트 편집 | 자연스럽다 | Poedit 필요 |

**고르는 기준은 하나다 — 복수형과 외부 번역 플랫폼을 쓰는가.**
쓰면 `.po`, 안 쓰면 CSV. 라리엔은 원본 1,116 키에 ICU `plural`·`select` 가 **0건**이라 CSV 다(실측).

> 🛑 **자체 JSON 로더를 만들지 않는다.** `tr()`·자동 번역·`NOTIFICATION_TRANSLATION_CHANGED`·에디터 POT 추출을
> 전부 버리게 된다. 원본이 JSON·ARB 여도 **빌드 전에 CSV 로 변환**하고 런타임은 엔진에 맡긴다.

## 2. 등록 — 임포트가 먼저다, 등록은 그다음

CSV 를 프로젝트에 **넣는 것만으로는 로드되지 않는다.** 공식 문서도 명시한다 —
"Once a CSV file is imported, it is not automatically registered as a translation source."

```
① res://i18n/laryen.csv 를 넣는다
② 임포트   godot --headless --path . --import
   → laryen.en.translation · laryen.ko.translation … 가 **CSV 와 같은 폴더에** 생긴다
     (🛑 .godot/imported/ 가 아니다 — 실측)
③ 등록   Project Settings > Localization > Translations,
        또는 project.godot 에 직접
```

```ini
[internationalization]

locale/fallback="en"
locale/translations=PackedStringArray("res://i18n/laryen.en.translation", "res://i18n/laryen.ko.translation")
```

> 🛑 **순서를 뒤집으면 첫 실행에 `Cannot open file 'res://…translation'` 이 뜬다.** 임포트 → 등록이다.

**한 locale 에 여러 리소스를 등록해도 된다** — 키가 합쳐진다(실측). 라리엔은 `laryen.csv`(원본 번역 이식본)와
`laryen3d.csv`(신규 문구)를 따로 두고 14개를 등록한다. 한 파일이 생성물이고 다른 파일이 수작업이라 섞지 않는 것이다.

### 관련 프로젝트 설정

| 키 | 기본값 | 뜻 |
|---|---|---|
| `internationalization/locale/fallback` | `"en"` | 현재 언어에 키가 없을 때 찾아볼 언어 |
| `internationalization/locale/test` | `""` | 에디터·실행에서 강제할 언어(테스트용). 비어 있으면 OS 언어 |
| `internationalization/locale/include_text_server_data` | `false` | ICU 데이터를 pck 에 넣는다(CJK 줄바꿈 사전 등, 수 MB). 4.4 에서 기본이 `false` 로 바뀌었다 |
| `internationalization/rendering/root_node_auto_translate` | `true` | 루트의 자동 번역 |
| `internationalization/rendering/root_node_layout_direction` | `0`(로케일 기반) | [§7](#7-rtl--자동이다-조작-ui-만-막는다) |

## 3. 화면에 쓰기 — 키를 넣으면 엔진이 번역한다

### 씬에 박는 문구 — 공짜다

`Label.text`·`Button.text`·`LineEdit.placeholder_text` 에 **번역 키**를 넣는다. 그러면 끝이다.

```
[node name="GuestButton" type="Button" parent="."]
text = "GUEST_LOGIN"        ← 화면에는 "손님 로그인" 이 그려진다
```

엔진 내부는 `xl_text = atr(text)` 다(4.7 `button.cpp`·`label.cpp`). `atr()` 은 `auto_translate_mode` 를 보는 번역 함수다.

| `auto_translate_mode` | 언제 |
|---|---|
| `AUTO_TRANSLATE_MODE_INHERIT`(기본) | 부모를 따른다. 루트는 프로젝트 설정 `root_node_auto_translate` |
| `AUTO_TRANSLATE_MODE_ALWAYS` | 항상 번역 |
| **`AUTO_TRANSLATE_MODE_DISABLED`** | **번역하지 않는다** — 🛑 플레이어 이름·채팅·서버 ID 처럼 **사용자 데이터를 그리는 노드는 반드시 이것** |

> 🛑 **닉네임이 번역되는 사고** — 플레이어가 이름을 `GUEST_LOGIN` 으로 지으면 그 Label 이 "손님 로그인" 으로 바뀐다.
> 우연이 아니라 구조적으로 가능하다. **사용자 데이터를 그리는 노드는 예외 없이 `DISABLED`.**

### 코드가 만드는 문구 — 내가 해야 한다

```gdscript
label.text = tr("GAME_TITLE")                                   # 키 → 현재 언어
label.text = tr("WELCOME_USER").format({"name": player_name})   # ✅ 이름 있는 자리표시자
label.text = tr("PICKED_UP") % [who, what]                      # 🛑 %s 는 언어마다 어순을 못 바꾼다
label.text = tr("CLOSE", "Actions")                             # 문맥
label.text = tr_n("%d apple", "%d apples", n) % n               # 복수형(?plural 열 필요)
```

**자리표시자는 이름으로 쓴다** — 공식 문서가 권장하고, 언어마다 어순이 달라도 `format()` 이 제자리를 찾는다.
`{name}` 형식은 Flutter ARB·ICU 와도 같아서 원본을 그대로 옮길 수 있다(실측: `"환영합니다, {name}님"` → `format({"name": "김철수"})`).

### 문구의 소유권 — 화면을 모르는 층은 키만 보낸다

```gdscript
# ❌ 인증 모듈이 완성 문장을 보낸다 — 언어를 바꿔도 이미 표시된 문장은 그대로다
status_changed.emit("손님 계정으로 접속하는 중…")

# ✅ 키를 보낸다. 번역은 화면이 한다
status_changed.emit("AUTH_GUEST_CONNECTING")
```

서버 예외 원문(`ex.message`)을 사용자 문구에 붙이지 않는다 — 그 부분만 영어로 남고 내부 사정이 노출된다.
로그(`push_error`)에는 남기고, 화면에는 **오류 분류 키**를 보여준다.

## 4. 언어 정하기 — 공식 예제가 네 줄이다

공식 문서 "Internationalizing games" 의 코드 그대로다.

```gdscript
var language = "automatic"
if language == "automatic":
    var preferred_language = OS.get_locale_language()
    TranslationServer.set_locale(preferred_language)
else:
    TranslationServer.set_locale(language)
```

| API | 무엇을 돌려주나 |
|---|---|
| `OS.get_locale()` | 플랫폼이 준 전체 로케일. macOS·iOS `ko_KR`·`zh_Hans_CN` · **Android `zh_CN_#Hans`**(Java `Locale.toString()`) · Linux `ko_KR.UTF-8` |
| **`OS.get_locale_language()`** | **언어 코드만.** 구현은 `get_locale().left(3).remove_char('_')` (4.7 `os.cpp`) → `ko_KR`→`ko`, `zh_Hans_CN`→`zh` |
| `TranslationServer.get_locale()` | 지금 적용된 로케일 |
| `TranslationServer.set_locale(l)` | 표준화해서 적용하고 **트리 전체에 알림을 보낸다** |
| `TranslationServer.standardize_locale(l)` | `language_Script_COUNTRY` 로 정규화. `ko-KR`→`ko_KR` · `sr@latin`→`sr_Latn` |
| `TranslationServer.get_loaded_locales()` | 로드된 번역들의 locale |

### 번역이 어떻게 골라지나 — `compare_locales`

`set_locale("ko_KR")` 인데 번역이 `ko` 뿐이어도 잡힌다. 엔진이 점수로 고르기 때문이다(4.7 `translation_domain.cpp`).

| 비교 | 점수 (실측) |
|---|---|
| 완전 일치 | **10** — 즉시 채택 |
| 언어만 같음 | **5** |
| 언어 같고 스크립트·국가가 다름 | 5 − 1씩 (`zh_TW` ↔ `zh` = **3**) |
| 언어가 다름 | **0** — 채택 안 됨 → `fallback` |

점수가 0보다 크면 후보이고 최고 점수가 이긴다. 키가 없으면 `fallback` locale 에서 한 번 더 찾고,
그래도 없으면 **키 문자열을 그대로 돌려준다** — 화면에 `GUEST_LOGIN` 이 보인다면 그 키가 표에 없다는 뜻이다.

### 지원 언어를 좁혀야 할 때

엔진 폴백에만 맡기면 **번역이 없는 언어의 로케일이 그대로 적용된다.** 아랍어 장치라면 문구는 영어인데
레이아웃만 RTL 이 된다(`set_locale("ar")` 이 레이아웃을 바꾼다 — 실측). 지원 목록을 두고 거기 없으면
영어 코드를 넣는 편이 안전하다.

```gdscript
const SUPPORTED := ["en", "ko", "ja"]

func apply_language(user_choice: String) -> void:
    var lang := user_choice
    if lang == "":                             # "System default"
        lang = OS.get_locale_language()
    if not SUPPORTED.has(lang):
        lang = "en"
    TranslationServer.set_locale(lang)
```

### 사용자 선택을 저장한다

공식 문서는 "플레이어가 언어를 고를 수 있게 하라"까지만 말하고 **저장 방법은 앱의 몫**이다.
Godot 의 표준 설정 저장은 `ConfigFile` + `user://` 다.

```gdscript
const PATH := "user://settings.cfg"

func save(language: String) -> void:
    var cfg := ConfigFile.new()
    cfg.load(PATH)                             # 다른 설정을 보존한다
    if language == "":
        cfg.erase_section_key("display", "language")   # System default = 키 삭제
    else:
        cfg.set_value("display", "language", language)
    cfg.save(PATH)
```

**오토로드로 두고 다른 오토로드보다 앞에 등록한다** — 첫 프레임 전에 언어가 정해져야 로그인 화면이
영어로 잠깐 보였다 바뀌는 깜빡임이 없다.

## 5. 즉시 교체 — 씬은 공짜, 코드는 내 몫

`TranslationServer.set_locale()` 이 하는 일 (4.7 `translation_server.cpp`):

```cpp
locale = new_locale;
ResourceLoader::reload_translation_remaps();
OS::get_singleton()->get_main_loop()->notification(MainLoop::NOTIFICATION_TRANSLATION_CHANGED);
```

`SceneTree` 가 그것을 받아 `get_root()->propagate_notification(...)` 으로 **트리 전체에 뿌린다**.
`Label`·`Button` 은 그 알림에서 `xl_text = atr(text)` 를 다시 계산한다. **재시작이 필요 없다.**

**코드가 만든 문자열은 엔진이 되돌릴 수 없다.** 키를 들고 있다가 다시 번역해야 한다.

```gdscript
var _status_key := ""

func show_status(key: String) -> void:
    _status_key = key
    status_label.auto_translate_mode = Node.AUTO_TRANSLATE_MODE_DISABLED  # 이미 번역문이다 — 두 번 번역 금지
    status_label.text = tr(key)

func _notification(what: int) -> void:
    if what == NOTIFICATION_TRANSLATION_CHANGED and _status_key != "":
        show_status(_status_key)
```

> 🛑 **번역문을 넣는 Label 은 자동 번역을 끈다.** 켜 두면 `tr()` 결과가 우연히 다른 키와 같을 때 또 번역된다.

## 6. 폰트 — 네모가 뜨는 이유는 번역이 아니라 글리프다

**번역이 정상인데 화면이 □ 인 경우가 있다.** 폰트에 그 글자가 없는 것이다. 번역 표를 아무리 고쳐도 안 바뀐다.

```gdscript
# 지금 폰트가 이 글자를 그릴 수 있는가 — 진단의 시작
print(ThemeDB.fallback_font.has_char("한".unicode_at(0)))
```

| 실측 (Godot 4.7.2 기본 폰트 Open Sans SemiBold) | |
|---|---|
| `A` | ✅ |
| 한글 `한` · 한자 `中` · 가나 · 데바나가리 `ह` · 아랍 `ز` · 벵골 `ব` | **전부 ❌** |

### 해결 — 폴백 체인

```
주 폰트 (라틴, 우리 브랜드)
 └─ fallbacks[0] : CJK 서브셋
     └─ fallbacks[1] : 데바나가리 …
         └─ 시스템 폰트 (allow_system_fallback = true, 기본값)
```

`FontVariation` 하나를 만들어 `base_font` + `fallbacks` 를 채우고 `gui/theme/custom_font` 에 등록하면 전 화면에 적용된다.

```
[gd_resource type="FontVariation" load_steps=3 format=3]
[ext_resource type="FontFile" path="res://assets/fonts/OpenSans_SemiBold.woff2" id="1"]
[ext_resource type="FontFile" path="res://assets/fonts/NotoSansCJK-Subset.otf" id="2"]
[resource]
base_font = ExtResource("1")
fallbacks = Array[Font]([ExtResource("2")])
```

> 🛑 **`fallbacks` 는 `Array[Font]` 다.** 코드에서 타입 없는 `Array` 를 대입하면
> `Trying to assign an array of type "Array" to a variable of type "Array[Font]"` 가 나고 **대입이 통째로 무시된다**(실측).
> `var order: Array[Font] = []` 로 선언하고 `append` 한다.

### 시스템 폰트 폴백 — 되지만 믿을 수는 없다

`allow_system_fallback`(기본 `true`)은 글리프가 없을 때 OS 폰트를 찾는다. 지원 플랫폼은
**Windows·macOS·Linux·Android·iOS**(공식 문서 "Using Fonts"). Android 는 `/system/etc/fonts.xml` 을
파싱한다(4.7 `os_android.cpp`, `OS.has_feature("system_fonts")` = true).

**실측 (Galaxy A12 · Android 12 · 폰트 번들 0)**

| | 결과 |
|---|---|
| 한글 · 데바나가리 · 아랍(RTL 셰이핑) · 벵골(결합 문자) · 국기 이모지 | ✅ 정상 |
| **일본어·중국어 한자** | 🛑 **□** |

**원인** — 삼성 `fonts.xml` 은 `<family lang="ko">` 에 **한자가 없는 SamsungKorean** 을 CJK 보다 앞에 등록한다
(주석에 "to be higher than the Google Font"). Godot 의 시스템 폰트 선택은
`lang` 일치 +120점 · `script` 필터로 후보를 고르는데 **그 폰트가 실제로 그 글자를 가졌는지 확인하지 않는다**
(`get_system_font_path_for_text`). 그래서 한국어 로케일에서 한자 런에 SamsungKorean 이 뽑히고 □ 가 된다.
**일본어 로케일로 바꾸면 정상**이라는 것이 원인을 확정해 준다.

> **결론 — 문구가 우리 손 안에 있는 글자는 번들한다.** 시스템 폴백은 닉네임·채팅처럼 무엇이 올지 모르는
> 글자의 안전망으로 두고, UI 문구가 쓰는 글자는 서브셋 폰트로 확실히 그린다.

### 서브셋 — 20MB 를 2MB 로

CJK 폰트는 통째로 16~20MB 다. 실제로 쓰는 글자만 남긴다.

```bash
uv run --with fonttools --with brotli python -m fontTools.subset \
  NotoSansCJKjp-Regular.otf --text-file=chars.txt \
  --output-file=NotoSansCJK-Subset.otf --layout-features='*' --no-hinting --desubroutinize
```

**무엇을 넣는가** — 번역 표에 실제로 쓰인 글자 + 상용 범위(중국 GB2312 1급 3,755자 · 일본 JIS X 0208 1급 2,965자 + 가나).
번역 문구만 넣으면 닉네임·채팅의 임의 한자가 깨진다.

| 실측 (라리엔) | 글자 수 | 크기 |
|---|---|---|
| 번역 문구의 한자만 | 1,213 | **0.58 MB** |
| + GB2312 1급 + JIS 1급 + 가나 | 5,212 | **2.36 MB** |
| 데바나가리 · 벵골 · 아랍 (번역 문구만) | 60 · 64 · 52 | 0.11 · 0.08 · 0.02 MB |

### 한자 자형 — 중국식과 일본식은 다르다

`直`·`骨`·`海` 는 중국(SC)과 일본(JP)에서 모양이 다르다. 한 폰트만 넣으면 한쪽 사용자에게 낯선 자형이 보인다.

> 🛑 **실측: `Font.set_language_support_override("ja", false)` 는 폴백 선택을 바꾸지 못한다.**
> `is_language_supported()` 는 `false` 를 돌려주는데, `Label.language = "ja"` 로 두고 그려도
> **자형이 그대로였다.** 엔진의 폴백 탐색은 글리프 유무만 본다.
>
> **그래서 `fallbacks` 의 순서로 정한다** — 표시 언어가 중국어면 SC 서브셋을 앞에, 그 밖이면 JP 를 앞에.
> 언어를 바꿀 때 배열을 재배치하면 된다(전환은 프레임 단위로 즉시 반영된다 — 실측).

### 그 밖

- **MSDF** — 저사양 모바일에서는 켜지 않는다(공식 문서가 기본 비용을 경고). 기본값이 이미 `false`.
- **밉맵** — UI 가 축소되는 화면(기준 1080 → 720 폰)에서는 `gui/theme/default_font_generate_mipmaps` 를 켜는 편이 글자가 덜 자글거린다.
- **이모지** — 시스템 이모지 폰트로 폴백된다(macOS·Android 실측 정상). 번들하면 수 MB 다.

## 7. RTL — 자동이다, 조작 UI 만 막는다

아랍어·히브리어·우르두는 **엔진이 알아서 처리한다.** BiDi 텍스트 방향, 앵커·여백 미러링, 정렬 반전,
`HBoxContainer` 자식 순서 반전까지 자동이다.

```gdscript
TranslationServer.set_locale("ur")
print(root.is_layout_rtl())   # true
```

> **실측 — RTL 은 번역 파일 유무와 무관하다.** 번역 리소스가 0개인 프로젝트에서도 `set_locale("ur")` 만으로
> `is_layout_rtl()` 이 `true` 가 된다. TextServer 의 `is_locale_right_to_left()` 가 로케일만 보기 때문이다.

| `Control.layout_direction` | 값 | 뜻 |
|---|---|---|
| `LAYOUT_DIRECTION_INHERITED` | **0**(기본) | 부모를 따른다 |
| `LAYOUT_DIRECTION_APPLICATION_LOCALE` | 1 | 앱 로케일 기준 |
| **`LAYOUT_DIRECTION_LTR`** | **2** | **좌→우 고정** |
| `LAYOUT_DIRECTION_RTL` | 3 | 우→좌 고정 |
| `LAYOUT_DIRECTION_SYSTEM_LOCALE` | 4 | OS 로케일 기준 |

**게임 조작 UI 는 미러링하면 안 된다.** 이동·공격 버튼의 좌우가 뒤집히면 조작을 다시 배워야 한다.
글자 방향과 **손가락 위치**는 다른 문제다.

```gdscript
# 조작 버튼 묶음만 LTR 로 못박는다 — 메뉴·대화상자는 자동 미러링에 맡긴다
%Buttons.layout_direction = Control.LAYOUT_DIRECTION_LTR
```

> 🛑 **`CanvasLayer` 에는 `layout_direction` 이 없다.** HUD 루트가 `CanvasLayer` 면 그 **자식 `Control`** 에 건다.

**아랍 문자 폰트를 고를 때** — 우르두 전통 서체 Nastaliq 은 세로로 크게 흐르는 서체라 버튼 안에서 잘리거나
행간이 무너진다. UI 에는 **Naskh 계열**(`NotoNaskhArabic`)을 쓴다.

## 8. 검증 — 화면 감이 아니라 숫자로

### 헤드리스 (창 없음)

```gdscript
extends SceneTree

func _init() -> void:
    for l in ["en", "ko", "ja"]:
        TranslationServer.set_locale(l)
        assert(tr("GUEST_LOGIN") != "GUEST_LOGIN")   # 키가 그대로면 번역이 없다
    quit()
```

```bash
godot --headless --path . -s res://tests/i18n_test.gd    # exit 0 이 합격
```

**함정 세 가지**

| 함정 | 왜 | 어떻게 |
|---|---|---|
| **영어 폴백이 미번역을 가린다** | `tr(key)` 가 fallback 번역을 돌려주므로 대상 언어에 키가 없어도 통과한다 | **CSV 원본을 직접 읽어** 빈 셀을 센다. 언어마다 값이 다른 **sentinel 키**(`i18nSentinel` = `"laryen:ko"`)를 넣어 두면 폴백이 왔는지 바로 들킨다 |
| `Translation.get_message_count()` 가 0 | 압축 임포트(`compress` 기본 켜짐)의 `OptimizedTranslation` 은 원문을 저장하지 않는다 | 키 수는 CSV 에서 센다 |
| `tr()` 로 자동 번역을 검사 | `tr()` 은 `auto_translate_mode` 와 **무관하게 항상 번역**한다 | 자동 번역 여부는 **`atr()`** 로 본다 — Label 이 그리는 문자열도 `atr()` 로 만들어진다 |

### 창 (스크린샷)

```bash
godot --path . --resolution 1280x720 -s res://tests/autopilot_i18n.gd
```

스크립트에서 `change_scene_to_file()` 로 화면을 열고, 언어를 바꾸며 기대 문자열과 비교하고,
`await RenderingServer.frame_post_draw` 뒤 `root.get_texture().get_image().save_png(...)` 로 남긴다.
**글리프가 실제로 그려지는지는 스크린샷으로만 확인된다** — `has_char()` 는 폰트 안의 유무일 뿐이다.

### 실기기

폰트 폴백은 **기기마다 다르다.** 제조사 ROM 의 `fonts.xml` 이 다르기 때문이다(§6).
`--export-debug` → `adb install -r` → `adb exec-out screencap -p` 로 실제 화면을 받아 눈으로 확인한다.

### 에디터에서 미리보기

- Project Settings → `internationalization/locale/test` 에 코드를 넣는다
- 에디터 메뉴 **View → Preview Translation**
- 실행 시 `godot --language ko`
- **의사 현지화**(`internationalization/pseudolocalization/*`) — 문자열을 늘리고 감싸서 **UI 가 넘치는 곳**을 미리 찾는다

## 9. 자주 막히는 곳

| 증상 | 원인 | 확인 |
|---|---|---|
| 화면에 `GUEST_LOGIN` 이 그대로 보인다 | 그 키가 표에 없거나, 번역이 등록되지 않았다 | `TranslationServer.get_loaded_locales()` · CSV 에 키가 있는가 |
| CSV 를 넣었는데 아무 일도 없다 | 임포트만 하고 **등록**을 안 했다 | `project.godot` 의 `locale/translations` |
| `Cannot open file 'res://….translation'` | 임포트 전에 등록했다 | `--import` 를 먼저 |
| 언어를 바꿨는데 일부만 바뀐다 | 코드가 만든 문자열이 남아 있다 | `NOTIFICATION_TRANSLATION_CHANGED` 에서 다시 `tr()` |
| 글자가 □ | 폰트에 글리프가 없다 | `font.has_char(…)` — 번역 문제가 아니다 |
| 한자만 □ (Android) | 제조사 `fonts.xml` × 엔진 선택 방식 | §6 — 서브셋을 번들한다 |
| 아랍어에서 버튼 좌우가 뒤집힌다 | 자동 미러링 | 조작 묶음에 `LAYOUT_DIRECTION_LTR` |
| 닉네임이 번역된다 | `auto_translate_mode` 가 켜져 있다 | 사용자 데이터 노드는 `DISABLED` |
| `fallbacks` 대입이 무시된다 | 타입 없는 `Array` 를 넣었다 | `var a: Array[Font] = []` |
| CSV 가 깨진다 | Excel 이 붙인 BOM·ANSI | UTF-8 no-BOM 으로 다시 저장 |
| `?plural` 을 썼더니 자동 번역이 안 된다 | 공식 제약 | `tr_n()` 을 손으로 부른다 |
